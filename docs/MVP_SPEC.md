> 서울의 물가 감각을 외국인에게 알려주는 서비스

| 항목 | 내용 |

## 1. 서비스 개요

### 1.1 문제
서울을 방문하거나 거주하는 외국인은 "이 가격이 비싼 건지, 적당한 건지"를 판단하기 어렵다. 환율 계산은 할 수 있어도 **현지 기준의 적정 가격대**를 모르기 때문에 바가지를 쓰거나, 반대로 적당한 가격에도 불안해한다.

### 1.2 해결
- 물건·음식의 **일반적인 가격대**를 검색으로 바로 확인
- **퀴즈**로 가격 감각을 재미있게 학습
- **히트맵**으로 지역별 물가 차이를 한눈에 파악
- 다른 외국인의 **실제 경험(리뷰)** 을 참고

### 1.3 타깃 사용자
- 서울 단기 여행객
- 유학생·주재원 등 서울 장기 체류 외국인
- 한국 방문을 준비 중인 예비 여행객

### 1.4 서비스 원칙
- **로그인 없음**: 누구나 바로 사용. 리뷰 수정·삭제는 글별 비밀번호로 처리
- **다국어 대비 설계**: MVP는 한국어로 먼저 만들고, 이후 영어 버전을 추가한다 (→ [9. 로드맵](#9-로드맵)). 처음부터 UI 문자열을 분리해 둔다
- **원화 기준 + 환산 보조**: 가격은 KRW로 보여주고 USD 등 환산 금액을 보조로 함께 보여준다

## 3. 기능 상세

### F1. 물가 검색

**사용자 스토리**
> 외국인 여행객으로서, "bibimbap"을 검색해서 서울에서 보통 얼마인지 알고 싶다. 그래야 메뉴판 가격이 적당한지 판단할 수 있다.

**요구사항**
- 검색어는 영어·한국어 모두 지원한다 (예: `bibimbap`, `비빔밥`)
- 별칭/동의어를 매칭한다 (예: `soju` ↔ `소주`, `kimbap` ↔ `gimbap` ↔ `김밥`)
- 검색 결과에 보여줄 정보
  - 품목명 (영문 / 한글)
  - **보통 가격대**: 최저~최고 범위 + 평균(또는 중앙값)
  - 단위 (1인분, 1병, 1개 등)
  - 환산 금액 (USD 등)
  - 기준 시점과 데이터 출처
  - 관련 리뷰 바로가기 (F4 검색 결과로 연결)
- 결과가 없으면 비슷한 품목을 추천하거나 "아직 데이터가 없음"을 안내한다

**결과 예시**
```
Bibimbap (비빔밥)
Usually ₩10,000 ~ ₩13,000 per serving (avg. ₩11,500 ≈ $8.30)
Source: 한국소비자원 참가격, 2026-10 기준
→ See 12 reviews mentioning "bibimbap"
```

**데이터**
- 와이어프레임 기준: **웹 검색(네이버/구글) 결과**를 기반으로 가격대를 산출한다
  - 검색 API(예: 네이버 검색 API)로 가격 정보가 담긴 결과를 가져와 금액을 추출하고 범위·평균을 계산
  - 검색 결과는 캐시해서 같은 검색어 반복 호출을 줄인다
- 공공 통계(F3 데이터 소스)에 있는 품목은 통계 값을 우선 사용하거나 함께 보여준다
- 출처가 웹 검색이면 "웹 검색 기반 추정치"로 명확히 표시한다

### F2. 오늘의 물가 퀴즈

**사용자 스토리**
> 외국인으로서, 매일 한 문제씩 가격을 맞혀보면서 자연스럽게 한국 물가 감각을 익히고 싶다.

**흐름**
1. 오늘의 품목을 보여준다: *"How much does **Samgyeopsal (삼겹살, 200g)** usually cost in Seoul?"*
2. 사용자가 가격을 **주관식(숫자)** 으로 입력한다 (KRW)
3. 채점 결과를 보여준다
4. 학습 카드를 보여준다: 정답 가격대, 짧은 설명(왜 이 가격인지, 지역/가게 유형별 차이, 팁), 관련 리뷰 링크

**출제 규칙**
- 개발자가 정한 **퀴즈 풀(pool)** 에서 하루에 한 품목을 고른다
  - 한국 대표 외식 (예: 김치찌개, 비빔밥, 냉면, 삼겹살, 짜장면, 삼계탕, 칼국수, 김밥)
  - 외국인이 자주 찾는 음식/물건 (예: 소주, 치킨, 떡볶이, 편의점 삼각김밥, 아메리카노, 지하철 기본요금, 티머니 카드)
- 품목을 고른 뒤 **LLM으로 문제 문구, 정답 가격대, 학습 카드 해설을 생성**한다
  - 정답 기준가는 LLM이 지어내지 않도록 F1/F3의 가격 데이터를 프롬프트에 넣어 근거로 쓴다
  - 하루 한 번 생성해 저장하고, 그날은 저장된 문제를 재사용한다
- 같은 날에는 **모든 사용자에게 같은 문제**가 나간다 (날짜를 시드로 결정)
- 최근 N일 안에 나온 품목은 다시 내지 않는다

**채점 기준 (초안)**

| 판정 | 조건 (정답 기준가 대비 오차) | 표시 |
| --- | --- | --- |
| 정답 | ±10% 이내 | 🎯 Spot on! |
| 근접 | ±25% 이내 | 👍 Close! |
| 오답 | 그 밖 | 그보다 싸다/비싸다 방향 안내 |

- 오차율 = `|입력값 - 기준가| / 기준가`
- 품목별로 허용 오차를 따로 설정할 수 있게 한다 (가격 편차가 큰 품목 대비)

**기록 (로그인 없이)**
- 연속 참여(streak), 정답률 같은 개인 기록은 브라우저 로컬 저장소에만 둔다
- 서버에는 익명 통계만 쌓는다 (예: "오늘 참여자 평균 추정가 ₩14,200") → 결과 화면에 "다른 사람들의 추정" 분포로 보여줄 수 있음 (선택)

### F3. 서울 물가 히트맵

**사용자 스토리**
> 외국인으로서, 서울에서 어느 지역이 비싸고 어느 지역이 저렴한지 지도에서 한눈에 보고 싶다.

**요구사항**
- 서울 지도를 **자치구(25개) 단위**로 색칠한 히트맵 (데이터가 허용하면 행정동 단위로 확장)
- 품목 선택: 전체 지수 또는 개별 품목(예: 김치찌개, 삼겹살)을 고를 수 있음
- 구를 누르면 상세 패널: 해당 구의 품목별 평균가, 서울 평균 대비 차이(%), 데이터 기준 시점
- 범례: 저렴 ↔ 비쌈 색상 스케일, 서울 평균 기준선
- 출처와 기준 시점을 지도 하단에 항상 표시

**데이터 소스 후보**

| 출처 | 내용 | 비고 |
| --- | --- | --- |
| 한국소비자원 **참가격** | 외식비·생필품 가격 | 외식비는 시·도 단위 공개가 중심이라 구 단위 히트맵에는 부족할 수 있음 |
| 서울시 **상권분석서비스** (우리마을가게) | 상권·업종별 점포 수, 매출 등 | 가격 자체보다는 상권 특성 데이터 → 보조 지표로 활용 |
| 서울 열린데이터광장 **생필품 농수축산물 가격 정보** | 자치구별 시장/마트 품목 가격 | 구 단위 비교에 적합한 후보 |
| 행정안전부 **착한가격업소** | 지역별 저가 업소 목록·가격 | 지도 위 마커로 활용 가능 |

> ⚠️ 각 데이터셋의 공간 단위, 갱신 주기, 이용 조건(API 키, 라이선스)은 구현 전에 확인해야 한다.

**데이터 처리**
- 공공 API/파일을 주기적으로(예: 월 1회) 수집 → 정제 → 자체 DB에 저장
- 수집한 데이터는 F1 검색, F2 퀴즈 정답 기준가에도 같이 사용한다

### F4. 외국인 찐 리뷰 게시판

**사용자 스토리**
> 외국인으로서, 다른 외국인이 실제로 가본 가게의 가격과 경험을 보고 싶고, 나도 로그인 없이 리뷰를 남기고 싶다.

**인증 방식: 익명 + 글별 비밀번호**
- 글을 쓸 때 작성자가 **닉네임(선택)** 과 **비밀번호(필수)** 를 정한다
- 수정·삭제할 때 비밀번호를 입력해 확인한다
- 비밀번호는 **해시(bcrypt 등)로만 저장**하고 평문으로 저장하거나 응답에 내보내지 않는다
- 비밀번호 확인 시도 횟수를 제한한다 (무차별 대입 방지)

**CRUD**

| 동작 | 권한 | 설명 |
| --- | --- | --- |
| Create | 누구나 | 닉네임, 비밀번호, 제목, 본문, 가게 태그, (선택) 지불 가격, (선택) 평점 |
| Read | 누구나 | 목록(최신순, 페이지네이션) / 상세 |
| Update | 비밀번호 일치 시 | 비밀번호를 제외한 모든 필드 수정 |
| Delete | 비밀번호 일치 시 | 글 삭제 |

**가게/상점 태그**
- 리뷰마다 가게 1개를 태그한다
- 태그 정보: 가게 이름, 카테고리(식당, 카페, 편의점, 시장 등), 위치(구 또는 주소)
- 이미 등록된 가게는 자동완성으로 고르고, 없으면 새로 등록한다
- 리뷰 항목 예시: "이런 점이 좋았다", 실제 지불 가격, 가격이 적당했는지(싸다/적당/비싸다)

**리뷰 검색**
- 물건/음식 이름으로 검색하면 **제목·본문·가게 이름에 해당 단어가 들어간 리뷰**를 보여준다
- F1 검색과 같은 동의어 사전을 써서 영어/한국어 모두 매칭한다
- F1 검색 결과의 "관련 리뷰" 링크는 이 검색으로 연결된다

**하지 않는 것 (MVP 범위 밖)**
- 댓글
- 좋아요/추천
- 사진 업로드 (추후 검토)

**운영 최소 장치**
- 신고 버튼 → 일정 횟수 이상 신고되면 숨김 처리 (선택)
- 같은 IP의 연속 작성 제한 (스팸 방지)
- 욕설/광고성 키워드 필터 (선택)

## 4. 데이터 모델 (초안)

> 최신 설계는 [DB_DESIGN.md](DB_DESIGN.md) 참고. 히트맵(F3)용 테이블은 그 문서에만 있다.

```text
Item                      # 검색/퀴즈 대상 품목
- id
- name_en, name_ko
- aliases[]               # 동의어 (soju, 소주 ...)
- category                # food / drink / goods / transport ...
- unit                    # per serving, per bottle ...
- quiz_enabled (bool)
- quiz_tolerance          # 품목별 허용 오차 (기본 10% / 25%)
- description_en          # 학습 카드 설명

PriceStat                 # 품목 가격 통계
- id
- item_id → Item
- region                  # 'seoul' 또는 자치구 코드
- price_min, price_avg, price_max
- source                  # 참가격 / 서울 열린데이터 / 자체 조사 ...
- reference_date          # 기준 시점

DailyQuiz
- date (PK)
- item_id → Item
- answer_price            # 채점 기준가 (해당 날짜의 PriceStat 기준)

QuizAnswer                # 익명 통계용 (선택)
- id
- date → DailyQuiz
- guessed_price
- result                  # correct / close / wrong
- created_at

Store                     # 리뷰에 태그되는 가게
- id
- name
- category
- district                # 자치구
- address (nullable)

Review
- id
- store_id → Store
- nickname (nullable, 기본 'Anonymous')
- password_hash
- title
- body
- paid_price (nullable)
- price_feeling           # cheap / fair / expensive (nullable)
- rating (nullable, 1~5)
- created_at, updated_at
```

## 5. API 초안

| Method | Path | 설명 |
| --- | --- | --- |
| GET | `/api/items/search?q=` | F1 품목 검색 (가격대 포함) |
| GET | `/api/items/{id}` | 품목 상세 |
| GET | `/api/quiz/today` | 오늘의 퀴즈 문제 (정답 제외) |
| POST | `/api/quiz/today/answer` | `{ guessed_price }` → 채점 결과 + 학습 카드 |
| GET | `/api/heatmap?item_id=` | 자치구별 가격 데이터 (item_id 없으면 종합 지수) |
| GET | `/api/stores?q=` | 가게 자동완성 |
| POST | `/api/stores` | 가게 등록 |
| GET | `/api/reviews?q=&page=` | 리뷰 목록 / 검색 |
| GET | `/api/reviews/{id}` | 리뷰 상세 |
| POST | `/api/reviews` | 리뷰 작성 (비밀번호 포함) |
| PUT | `/api/reviews/{id}` | 리뷰 수정 (요청 body에 비밀번호) |
| DELETE | `/api/reviews/{id}` | 리뷰 삭제 (요청 body에 비밀번호) |

- 비밀번호는 URL 쿼리에 넣지 않고 항상 요청 body로 보낸다
- 응답에는 `password_hash`를 절대 포함하지 않는다

### 6.1 홈 화면 와이어프레임

```text
┌───────────────────────────────────────────────┐
│ ① [ 검색창 ........................... 🔍 ]   │ ← 네이버/구글 검색 기반
├───────────────────────┬───────────────────────┤
│ ② 오늘의 퀴즈 →       │ ③ Heat map →          │ ← 한국소비자원
│ ┌───────────────────┐ │ ┌───────────────────┐ │
│ │                   │ │ │  (서울 미니 지도)  │ │
│ │   퀴즈 카드       │ │ └───────────────────┘ │
│ │                   │ │ ④ Review →            │ ← 자체 개발
│ │                   │ │ ┌───────────────────┐ │
│ └───────────────────┘ │ │  최신 리뷰         │ │
│   ↑ LLM 문제·답 생성  │ └───────────────────┘ │
└───────────────────────┴───────────────────────┘
```

- 각 섹션 제목 옆 `→`를 누르면 해당 기능의 전체 화면으로 이동한다

### 6.2 화면 목록

| 화면 | 주요 요소 |
| --- | --- |
| 홈 | 검색창, 오늘의 퀴즈 카드, 히트맵 미리보기, 최신 리뷰 |
| 검색 결과 | 가격대 카드, 출처/기준일, 관련 리뷰 목록 |
| 퀴즈 | 문제 → 가격 입력 → 결과 + 학습 카드 |
| 히트맵 | 서울 지도, 품목 선택, 구 상세 패널, 범례 |
| 리뷰 목록 | 검색창, 리뷰 카드 목록, 글쓰기 버튼 |
| 리뷰 상세 | 본문, 가게 정보, 수정/삭제 (비밀번호 입력 모달) |
| 리뷰 작성/수정 | 닉네임, 비밀번호, 가게 태그, 가격, 본문 |

## 7. 비기능 요구사항

- **모바일 우선**: 여행 중 휴대폰 사용이 주 사용 환경
- **성능**: 검색 응답 1초 이내 목표
- **보안**: 비밀번호 해시 저장, 쓰기 API rate limit, XSS 방지(리뷰 본문 이스케이프)
- **데이터 신뢰성**: 모든 가격에 출처와 기준 시점을 표시
- **다국어 확장성**: UI 문자열을 처음부터 분리해 두어 영어 버전(로드맵 1단계)을 쉽게 추가할 수 있게

## 9. 로드맵

MVP(F1~F4)의 최소 구현을 마친 뒤 아래 순서로 추가한다.

| 단계 | 기능 | 내용 |
| --- | --- | --- |
| 0 | **MVP** | F1 물가 검색, F2 오늘의 퀴즈, F3 히트맵, F4 리뷰 게시판 (한국어) |
| 1 | **영어 버전** | 전체 UI 영어 번역, 언어 전환, 품목명 영/한 병기, 영어 검색어·동의어 지원, 환산 금액 표시 |
| 2 | **메뉴판 인식 OCR** | 메뉴판/가격표 사진 촬영 → OCR로 메뉴명·가격 추출 → 품목별 보통 가격대와 비교해 "비싼가?" 판정 |

### 2단계: 메뉴판 OCR 흐름 (초안)

```text
[⊕ 이미지 촬영/업로드] → WonSense (OCR + 메뉴명 매칭) → "비싼가?" 결과
```

1. 사용자가 메뉴판 사진을 찍거나 업로드한다
2. OCR로 메뉴명과 가격을 추출한다
3. 메뉴명을 F1의 품목/동의어 사전과 매칭한다
4. 메뉴별로 판정한다: **저렴 / 적당 / 비쌈** (보통 가격대 대비 %)
5. 매칭되지 않은 메뉴는 "데이터 없음"으로 표시한다
